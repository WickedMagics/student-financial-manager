## Project Identity
- Name: Student Financial Manager
- Build method: KDBM Lite (Spec -> Build -> Check -> Ship)

## Build Shape
Browser-local tool. The main value is creating and changing the user's own financial data, kept after refresh in the same browser. No server, no login, no backend.

## Version-One Promise
A Gen Z-friendly, warm terracotta single-page money tracker where a student adds expenses via dropdowns, logs income, sets savings goals, sees a monthly summary, and keeps everything in their browser.

## Scope Lock
### Now
- Single-page browser app (Vite + React + plain CSS).
- localStorage persistence under key `sfm-data`.
- Sample data seeded on first open.
- Add Expense (dropdowns: category, amount, date, payment method; optional note).
- Add Income (dropdowns: source, amount, date; optional note).
- Add Goal (name, target amount, optional deadline; currentAmount starts at 0).
- Edit and delete any entry.
- Dashboard summary: Income, Expenses, Remaining, Savings Rate for current month.
- Goal progress bars.
- Friendly tip of the day.
- Empty state with a sample-data button.
- Mobile-first responsive layout.

### Later
- CSV export.
- Multiple month filtering.
- Budget caps per category with warnings.
- Streaks and achievement badges.

### Never
- Backend, server, database, auth, login.
- Real bank or e-wallet API connections (TNG is a label only).
- Payments, checkout, commerce.
- Multi-user sync or data sharing.
- Invented metrics presented as real.

## Architecture Summary
Single-page app. Root component `App` holds all state and localStorage logic. Components: SummaryCard, EntryForm (with Expense/Income/Goal tabs), EntryList, GoalList, TipOfTheDay, EmptyState. One combined data array in localStorage; each entry has a `type` field.

## Data / State / Storage Rules
- Storage key: `sfm-data` (single array).
- Read on mount; write on every change.
- Seed sample data when storage is empty.
- Amounts stored as numbers.
- Expense: id, type="expense", category, amount, date, method, note(optional).
- Income: id, type="income", source, amount, date, note(optional).
- Goal: id, type="goal", name, targetAmount, currentAmount, deadline(optional).

## Design Direction Summary
Borrow from Ember Studio: warm terracotta (#C2410C) single interactive accent, amber (#F59E0B) sparingly, warm off-white cards (#F5F5F4), cream background (#FAFAF9), 4px spacing grid, serif headings (Playfair Display) + sans body (Source Sans 3), flat cards with 1px warm border and 12px radius, terracotta primary buttons with 8px radius, 4px progress bars, pill chips.
Do not copy: Ember branding, logo, copy, testimonials, photos, or the sidebar layout. Adapt style only. No blue anywhere. One primary CTA per view. No fake claims or lorem ipsum.

## Implementation Rules
- Vite + React + plain CSS. No Tailwind, no backend.
- Dropdowns for category/source/method — no free-text for those fields.
- One primary CTA per view (terracotta).
- Max two font weights per screen.
- Use the 4px spacing scale.
- Amounts as numbers; compute totals with reduce.
- localStorage read on mount, write on change.
- Sample data clearly labeled as sample.
- No secrets, no API keys, no invented data.

## File and Folder Expectations
- index.html — single HTML entry, loads React from CDN.
- App.jsx — root component with state and storage logic.
- components/*.jsx — individual components.
- styles.css — all styling.
